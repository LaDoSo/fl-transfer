# FLP 格式笔记

只记录在真实文件上验证过的内容。样本：本机 142 个 `.flp`（FL 20.5 到 25.2.5）、612 个 `.fsc` / `.fst`，以及 FL 25.2.5 重新保存的对照文件。

## 容器

```
"FLhd" <u32 长度=6> <u16 format> <u16 通道数> <u16 ppq>
"FLdt" <u32 长度> 事件 事件 …
```

事件 = 一字节 ID + 数据，数据长度由 ID 决定：

| ID | 数据 |
|---|---|
| 0–63 | 1 字节 |
| 64–127 | 2 字节 |
| 128–191 | 4 字节 |
| 192–255 | 变长：7 位一组的长度前缀，然后是数据 |

文本是 UTF-16-LE。header 的 format：工程 0，乐谱 `.fsc` 16，通道预设 `.fst` 32。

**例外**：FL 25.2.3 起，事件 172 只有 3 字节数据，后面紧跟事件 192。按上表读不会报错，写回也逐字节一致，但之后的内容全部错位。判断规则：版本 ≥ 25.2 且第 4 个字节是 192 时按 3 字节读。逐字节回写一致不能证明解析正确，要另外检查通道数和音符块长度（`Project.sanity()`）。

## FL 25.2.5 工程的事件顺序

1. 文件头：`199`（版本文本）`159 169 28 172 192 37 200 156 67 …`，若干 `231`（通道分组名），然后 `146 216`。
2. 每个有音符的 Pattern 一对 `65 <编号>`、`224 <音符>`。
3. `226 ×3`，可选 `227`。
4. 第一个通道块；紧接着是 Pattern 的名称颜色块（`65 [193 名称] 150 157 …`）；然后是其余通道块。
5. `99`（编排开始）`241 36 233`，500 对 `238 43`（轨道），混音台。事件 99 之后没有任何 Pattern 相关内容。

## 通道块

- 以 `64 <iid>` 开头。iid 按文件顺序是 0..n-1，n 等于 header 里的通道数。
- 结尾是 `… 143 20 [196] 170 51`。
- 事件 21 是类型：0 Sampler，2 插件，3 Layer，4 音频片段，5 自动化。
- 事件 196 采样路径，可带 `%FLStudioFactoryData%`、`%FLStudioUserData%` 前缀。
- 事件 104（2 字节）是混音台插槽，0 为主轨。FL 20 用事件 22。
- 事件 145（4 字节）是通道分组的序号，对应文件头里第几个 `231`。
- 插件状态在事件 212、213，整段复制即可。

## 音符

事件 224，每个音符 24 字节，`<IHHIHHBBBBBBBB`：位置（tick）、标志、通道 iid（偏移 6）、长度（偏移 8）、音高，其余是力度、声像等。复制到别的工程要改通道 iid；两边 ppq 不同时，位置和长度按比例换算。

FL 1.x–3.x 的旧 `.fsc` 音符块不是 24 的倍数，解析器标记为 legacy，不做检查。

## 合并一个工程需要改的地方（已由 FL 25.2.5 打开并另存验证）

- 新通道块插在事件 99 之前，iid 取原通道数，header 通道数加一。
- 插槽（104）改为 0，分组（145）按名字对应到目标工程的分组。
- 新 Pattern 的 `65 224` 插在第一个 `226` 之前，名称颜色块插在已有的名称颜色块之后，编号取最大编号加一。
- FL 另存后的文件和工具写出的文件不会逐字节相同（FL 会重排和补字段），但通道、Pattern、音符一个不少。用 `tools/compare.py` 比较。

## 预设和乐谱文件

- `.fsc`：`199 159 169 28 172 192 37 65 224`，`65` 的值是 0，音符的通道字段是 0。
- `.fst`（通道预设）：同样的前导事件，后面是一个完整的通道块。

## 把文件交给正在运行的 FL（FL 25.2.5 实测）

FL 开着时再执行 `FL64.exe <文件>`，不会开第二个 FL，文件交给已运行的那个：

| 文件 | 结果 |
|---|---|
| `.fst` | 当前工程新增一个通道，名字取文件名，采样和设置都在 |
| `.fsc` | 音符加进当前 Pattern，落在新建的 `ScoreTrack` 通道（Sytrus）上；原有音符保留 |
| `.flp` | 替换当前工程 |
| `.wav` | 没有任何变化 |

### 一个 `.fst` 里同时带通道和 Pattern

`.fst` 可以有多个通道块，后面还可以跟 Pattern。FL 读它时的行为：

- 每个 `64` 通道块新建一个通道，排在现有通道后面。文件里 `64` 的值被忽略。第一个新通道的名字取文件名，其余保留自己的名字。
- `65 <n>` + `224`：音符写进目标工程的 Pattern n（不存在就新建）。`65 <n>` + `193` / `150`：给 Pattern n 起名、上色。一个文件里可以有多组，对应多个 Pattern。
- **音符的通道字段是目标工程里的绝对位置**，不会跟着新通道重排。要让音符落在文件带来的第 k 个通道上，字段要写“目标现有通道数 + k”。
- 通道字段指向已有通道：音符落在那个已有通道上。指向不存在的通道：保存工程时 FL 弹出 “There are invalid notes in this project. These notes will be deleted when the project is saved.”
- 文件里没有通道块、只有音符：FL 仍然新建一个空采样器通道。
- 采样器、原生插件（BENDY）、VST（Spire、Serum）通道都这样带过去了，插件状态在。

工具用的事件顺序：前导事件，全部通道块，然后每个 Pattern 一组 `65 224`，紧跟它的 `65 193 150…`。文件头的 PPQ 写目标工程的值，音符的位置和长度按比例换算。

FL 没有办法从外部查询当前工程的通道数。工具读目标工程上次保存的文件，并在 `%TEMP%\FLTransfer\targets.json` 里记下本次 FL 运行期间自己发过去的通道数和 Pattern 数（按文件的修改时间和 FL 的进程号区分，任何一个变了就清零）。

### 试过但没用的写法

- `.fst` 里音符的通道字段照抄来源工程的通道号：音符落在目标工程里**同号的已有通道**上，新通道是空的。
- `.fst` 里通道块后面只带 `224`（没有 `65`）：音符进入当前选中的 Pattern，早先一次实验里那个 Pattern 原有的音符被替换掉了。不要这样写。
- `.fsc` 里附带通道块（放在音符前或后）：通道块被忽略，仍然建 `ScoreTrack`。FL 导入乐谱时固定用 `Data\System\ScoreTrack.fst` 这个模板建通道。
- 钢琴卷帘里的复制不经过 Windows 剪贴板，没法从剪贴板送音符进去。

其他：Pattern 和通道的颜色存在事件 `150` / `128` 里，前 3 个字节当作 R、G、B 读取。工程搬到别的电脑后采样路径会失效，工具会在工程所在文件夹里按文件名找同名文件，导出的预设指向找到的位置。

FL 的窗口没有 `WS_EX_ACCEPTFILES` 样式，拖放走的是 OLE，不能用 `WM_DROPFILES` 消息模拟。

## 发送之后让 FL 显示新 Pattern（2026-11-15 实测，FL 25.2.5）

- FL 收到 `.fst` 后停在原来选中的 Pattern 上。新通道出现在机架最下面，但那一行显示的是当前 Pattern 的内容，所以是空的。
- 在 `.fst` 末尾加事件 `67 <n>`（当前 Pattern 号）：FL 内部的当前 Pattern 确实变成 n（之后存盘的文件里 67 = n），但界面只刷新了一部分，顶部选择器仍显示旧的号，机架里新旧 Pattern 的内容混在一起。不采用。
- 向 FL 主窗口投递数字小键盘的按键有效，且界面完整刷新：`VK_NUMPAD1..9` 直接选中 Pattern 1–9（重复按不会变），`VK_ADD` / `VK_SUBTRACT` 是下一个 / 上一个。10 号以上用“小键盘 9，再按若干次加号”。
- 携带文件的那个 `FL64.exe` 进程要等运行中的 FL 把文件加载完才退出（Serum 约 1.3 秒，Omnisphere 更久），可以用它的退出当作“加载完成”。
- 加载过程中插件自己可能弹提示框（例如 Omnisphere 的 library index 提示），这时 FL 主窗口是禁用状态，不能投递按键，要等它关掉。
- 关闭保存确认框（`TMsgForm`）：点击消息要投递给按钮子窗口（`TQuickFocusBtn`），投给对话框本身只会把它拖走。
